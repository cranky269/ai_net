## 2. 采集与硬件参数

| 参数 | 数值 | 状态 |
|---|---|---|
| 接收设备 | 软件无线电 USRP-2955 | 已核实 |
| 采样率 | **80 MHz（80 MS/s）** | 已核实 |
| 中心频率 | **2.44 GHz** | 已核实 |
| 频率范围 | 2.4 ~ 2.48 GHz（80 MHz 带宽） | 已核实 |
| 单片段采样时长 | **50 ms** | 已核实 |
| 单片段采样点数 | ≥ 4×10⁶（50 ms × 80 MS/s = 4×10⁶） | 已核实 |
| 采集距离 | 无人机/遥控器与接收机直线距离 10 m | 已核实 |
| 采集场景 | 城市户外/室内，含 Wi-Fi、蓝牙等干扰 | 已核实 |
| 场景标注 | `IN` = 视距（LOS），`OUT` = 非视距（NLOS） | 已核实 |
| LOS/NLOS 信噪比差异 | 约 **20 dB** | 已核实 |
| 信号成分 | 无人机飞控信号（FCS）、图传信号（VTS）、周边干扰设备信号 | 已核实 |
| 无人机通信频段设置 | 2.4 GHz | 已核实 |

**对本项目的直接影响**：

- `fs = 80 MHz`，`T = 50 ms`，单片段 4M 点。若原样送入 STFT，单个时频图规模极大，必须先分段（slice）或降采样；
- 频率分辨率由 STFT 窗长决定，例如窗长 256 → 312.5 kHz/bin，窗长 1024 → 78.125 kHz/bin；
- 城市环境自带 Wi-Fi/蓝牙干扰，属于“真实背景噪声”，与后续人为注入的高斯白噪声叠加时需要在报告中说明两者区别；
- LOS 与 NLOS 天然相差约 20 dB，相当于数据集自带两档“低信噪比”，可作为交叉验证的天然分组维度。

## 3. 文件组织与目录结构

顶层为两个目录（官方已预先划分）：

```
DroneRFb-DIR/
├── train/                  # 训练集：文件名即标签
│   ├── A1_IN_S0_slice_2.mat
│   └── ...
└── test/                   # 测试集：文件名为标号，无含义
    ├── xxxx.mat
    ├── ...
    └── test_labels.txt     # 标号 → 标签 的映射表
```

| 目录 | 组织方式 | 说明 |
|---|---|---|
| `train/` | 文件名直接编码标签 | 可直接从文件名解析机型、个体、场景、采集批、片段序号 |
| `test/` | 文件名为无意义标号 | 标签需查 `test_labels.txt`，便于“盲测”式算法验证 |

**风险提示**：官方 train/test 的划分比例与划分粒度（是否按个体、按记录、按场景分层）**页面未披露**。若官方划分是按片段随机拆分，则同一原始记录的不同 slice 可能同时出现在训练集与测试集，构成**数据泄漏**，与本题目“以原始记录为单位分组划分”的要求冲突。

## 4. 文件命名规则

示例：`A1_IN_S0_slice_2.mat`

| 字段 | 含义 | 取值 |
|---|---|---|
| `A1` | 机型字母 + 个体编号 | 机型 `A/B/C/D/E/F/G`，个体编号 `1/2/3`（B 为背景，无编号） |
| `IN` | 采集条件 | `IN` = 视距（LOS），`OUT` = 非视距（NLOS） |
| `S0` | 采集批次（时间序号） | `S0`、`S1` … |
| `slice_2` | 同一记录内的片段序号 | 整数递增 |

**注意**：论文中另出现 `A1_OUT_slice_4.mat` 这类**省略 `S` 字段**的命名，说明不同采集批次的命名存在细微不一致，解析时需要容错（正则建议按“可选 `S` 段”处理）。

**推导出的“原始记录”标识**：`机型个体 + 场景 + 采集批`，即 `A1_IN_S0`。同一记录下所有 `slice_k` 才是同源样本，**划分数据集时必须以该三元组为分组单位**，否则同源片段跨集合泄漏。

## 5. 标签体系

共 **19 个个体标签** = 6 类机型 × 3 架个体 + 1 类背景：

| 个体标签 | 机型 |
|---|---|
| A1, A2, A3 | DJI Mavic 3 Pro |
| **B** | **背景（background）参考信号** |
| C1, C2, C3 | DJI Mini 2 SE |
| D1, D2, D3 | DJI Mini 4 Pro |
| E1, E2, E3 | DJI Mini 3 |
| F1, F2, F3 | DJI Air 3 |
| G1, G2, G3 | DJI Air 2S |

**可用于两种任务粒度**：

1. **型号级（7 类）**：A/B/C/D/E/F/G，与题目“CNN 型号识别”的表述一致；
2. **个体级（19 类）**：A1…G3 + B，用于区分同型号不同个体，任务更难。

**类别不均衡风险**：总 4,690 段 ÷ 19 标签 ≈ 247 段/标签，但下限仅“≥40 段”，说明各类样本量差异明显。评估时应关注 Macro-F1 与混淆矩阵，而非仅看总体准确率。

## 6. 数据格式与读取方式

`.mat` 文件实为 **HDF5**，内含 `I`、`Q` 两个通道：

```python
import h5py
import numpy as np

with h5py.File("A1_IN_S0_slice_2.mat", "r") as f:
    keys = list(f.keys())            # 预期 ['I', 'Q']
    iq = f["I"][0] + 1j * f["Q"][0]  # 复数 IQ 序列
```

**待核验疑点**：原文称数据类型为“单精度浮点型（2 字节）”，但常规 `float32` 占 4 字节，两者矛盾。首次读取时必须打印 `dtype`、`shape`、`nbytes` 实测确认，再据此估算内存（4M 点 × complex64 ≈ 32 MB/段，全量读入约 150 GB，**不可整体载入内存**）。

**推荐读取策略**：

- 逐文件读取，单个片段内按固定长度切片生成 STFT，切片完成后即释放原始 IQ；
- 中间结果（时频图数组）落盘为 `.npy`/`.npz`，避免重复解码 `.mat`；
- 内存峰值控制在单文件量级（< 100 MB）。

## 8. 数据集使用限制与风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 体积过大 | 68 GB 原始 + 解压后更大 | 先做精简子集跑通链路，或按需下载 |
| 单段过长 | 4M 点 / 50 ms，直接 STFT 图过大 | 段内二次切片（如每 4096 点一帧） |
| 官方划分可能泄漏 | 划分粒度未披露 | 忽略官方 `train/test`，按 `个体+场景+批次` 重新分组划分 |
| 类别不均衡 | 各类样本量差异明显 | 分层划分 + Macro-F1 + 混淆矩阵 |
| LOS/NLOS 差异 20 dB | 天然两档信噪比 | 作为分组/分层维度记录，实验中单独统计 |
| 真实干扰非白噪声 | 城市 Wi-Fi/蓝牙干扰 | 报告中区分“采集背景干扰”与“人为注入高斯白噪声” |
| dtype 表述矛盾 | 2 字节 vs float32 | 读取时实测校验 |
| 命名不一致 | 部分文件缺 `S` 字段 | 解析用容错正则 |

## 9. 与本项目实验设计的衔接

依据题目要求，数据集在本项目中的使用方式如下：

1. **读取**：`h5py` 逐文件读 `I/Q`，重采样/切片到统一长度；
2. **分组划分**：以 `个体标签 + IN/OUT + S批次` 为分组键，分层划分为训练/验证/测试，保证同源片段不跨集合；
3. **加噪**：在划分完成后，对 IQ 时域序列按目标 SNR 注入高斯白噪声，噪声标准差由信号功率反推，固定随机种子保证可复现；
4. **STFT**：`fs = 80 MHz`，窗长/帧移/窗函数作为可调参数统一配置；
5. **预处理**：均作用于**加噪后的 IQ 时域序列**，再生成 STFT 时频图送入 CNN；
6. **评估**：各 SNR 档位下对比“加噪不预处理（基准）”与“加噪+各预处理方法”。

**加噪参考公式**（目标 SNR 反推噪声标准差）：

```
SNR_dB = 10 * log10(P_signal / P_noise)
P_signal = (1/N) * Σ|x[n]|²
σ_noise  = sqrt(P_signal / 10^(SNR_dB/10))
n = σ_noise / sqrt(2) * (n_I + j*n_Q),  n_I, n_Q ~ N(0,1)
y = x + n
```
